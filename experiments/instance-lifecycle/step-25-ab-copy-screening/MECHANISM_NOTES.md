# 可以归因到哪个窗口，哪些解释仍是假设

以STAGE_EFFECTS逐对差为依据，不能把各列中位数相加得到总中位数，也不能把`_start`全算作A或B1。

三优先合约中，G1→G2的S1→S2节省中位数约0.74–0.79ms，是A增量的主要可重复窗口；Copy耗时并未大幅减少。结合A原型和旧布局诊断，这与启动堆布局改变相符；本轮plain未直接计量sysReserveAligned/clear字节，不能重新确认具体清零分支的独占贡献。

G1→G3中，S0→S1节省约0.22–0.48ms，但S1→S2增加约0.27–0.33ms。因此B1/PB裁剪并非必然净受益；ERC721本轮完整Invoke呈负增量，compute波动明显。已确认的是窗口相抵，不是已定位某个package函数变慢。

历史布局证据显示PB裁剪也改变module_end/初始页/首次heap预留位置，因此更小WASM可能改变后续对齐和clear距离；这是可检验的候选解释。当前没有对同WASM单独保持所有布局量不变的控制，不认定“因为PB减少导致某缓存变差”等具体机制已证实。

G2→G4直接测量B1在A+Copy基础上的增量；与G1→G3的条件效果可以并列描述，但不能把两组独立Median相减后声称已测得统计交互。本轮不是完整三因子设计，且各条边在不同有界进程中测量；真正交互量仍需专门共同匹配设计。本轮保持负向和CI跨零结果，不补改工作负载。

normalCal需要结合最终STAGE_EFFECTS看export.Call、S1/S2的直接变化。即使本轮Fresh下某组更快，也不等于解释了历史R0/R1约8ms差异；本轮没有复用组，且二进制家族不同。
