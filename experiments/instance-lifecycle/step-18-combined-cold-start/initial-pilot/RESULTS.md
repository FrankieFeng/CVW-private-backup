## 启动阶段证据与内存代价

以下A/B1来自独立诊断构建；诊断有不同静态布局，单独校准，绝对值不能和plain Invoke相加。A首次预留点对齐验证通过，三个合约开启A均为bloc4194304、对齐距离0；关闭A分别需要跳过约1.5MiB。该距离来自函数入口bloc与alignUp之差，并非全部memclr调用的计数。源码的首个arena预留路径及旧clear探针支持该优化方向，不将仅增大initial memory当作A。

|合约|诊断A耗时 A0→A1 ms（C0）|诊断B1耗时 A0→A1 ms（C0）|plain `_start` A0→A1 ms（C0）|
|---|---|---|---|
|compute|2.265 → 0.511|0.325 → 0.307|2.811 → 0.946|
|erc721|1.691 → 0.442|0.279 → 0.255|1.990 → 0.720|
|fact|1.697 → 0.476|0.247 → 0.260|2.058 → 0.733|

A主要改善证据位于runtime启动：首次arena跳过空间消失，诊断A和未插桩_start下降；B1未作PB裁剪，不能把B1的小幅变化认定为PB优化。C减少S0→S1，Copy本身仍有约5万个范围循环及内存写入成本，参见summary的copy_ns。

每个合约只保留一个选定版本时，三个C模板逻辑容量合计 11.640 MiB（A0）→16.204 MiB（A1），约增加4.563 MiB。A使S1每Instance初始memory也增加约1.44–1.56MiB；实际稀疏Copy bytes仅增加174–361字节，不等于把padding全量拷贝。WASM只增加约645–668字节，因为零区间并未全量编码进Data。模板完整image仍保留零区间，存在明确内存代价。

模板构建每组30次，内存用独立GC前后保留对象差核查。仅以本批 C_on_A 的配对节省估计，A1模板预计算约需5/8/8次调用摊销（compute/ERC721/fact）；这是热Module VM内的粗略估计，不含编译/部署/存储/节点成本，不是生产盈亏点。

plain测试进程最大RSS约0.80–1.19GiB（各进程共存四个实验Module，执行180次fresh调用含预热，另有建池验证实例）。这不能等同单个缓存条目大小；native Store保留native对象的既有限制仍在，Instance.Close不代表所有native占用立即下降，进程/Store结束后统一回收。

## 正确性与尚未覆盖部分

12个P0组合的已测试范围通过：S1 Memory hash、S1 Globals、业务输出/写集/事件、同逻辑WASM的registry/native启动和业务Gas、Memory/Globals fresh隔离、模板不变性。静态Function/Code/Table/Element/Global节C0/C1相同，全表nullness在S1/S2/S3核查。真实Table函数身份为not_tested，不能称Table完全动态等价。

跨A：本批registry与native业务Gas一致，但native初始化+SetGas计量均增加16，符合新增init代码的观测；这不等于不同WASM总Gas相等，也没有认证新二进制Gas政策可接受。P引起的Gas变化没有数据。

ERC721非法tokenId、fact非法time实际进入guest错误路径，C0/C1结果/写集/事件/Gas一致。compute未验证guest业务异常；所有合约测试missing export的host dispatch错误。既有VM会打印method not export，但API结果仍是code0/空结果，本轮如实记录，不把它当正确的guest错误返回，也没有修改该行为。OOG、所有host trap及真实跨合约均not_tested。

第一次检查脚本因变体Label在循环中被覆盖而中断（第二个C池的序列化路径错误），已修复测试脚本，保留failed-harness原始日志并完成重查；不影响此前plain性能函数/样本。性能binary及其当时test源码单独保留在binaries/performance.test、prototype/performance_test.go.txt。

所有组safe字段均未认证；step-17缓存回收、共享Store并发race、真实Table身份限制未解决，不能生产启用。
