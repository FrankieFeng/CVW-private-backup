# Step-19统一指标：按用户确认采用合理且可复算的口径

用户已说明不必继续等待王浅秋原公式确认，按合理理解计算。本文件固定后续协议，取代“必须先确认PPT入口才能计算/推进”的条件；历史PPT对应脚本版本未知仍保留为资料限制，不能声称逐字复现了其公式。

主指标：

```
VM日志TPS = N / (sum(endTime - startTime) / 1e9)
```

N为选定批次、目标合约/方法的完整业务Invoke记录数，失败的完整Invoke也保留，防止悄悄删除失败开销。同时单列成功数、失败数、超时/缺失数及成功率；有失败或缺失的组不能仅凭主指标宣称有效性能提升。全部成功时，主指标等于平均Invoke秒数的倒数，不是Median倒数，也不是逐条倒数后平均。

统一规则：

1. 起止仍为vm_factory中的runtimeInstance.Invoke前后，保持代码边界不变；使用原始纳秒差，不以六位小数日志反推精确时长。
2. 显式排除部署、init_contract、upgrade_contract、预热；按批次、方法筛选后，分子分母使用完全相同的记录。正常业务调用嵌套阶段不可重复累加。
3. 根调用和跨合约子调用分别统计，主表使用根调用；另报每笔交易的attempt次数。不同节点、同TxID的重复执行属于不同VM执行事件，不按TxID合并为一次。
4. 重复采集的同一条日志仅按(node, TxID, depth, start, end)去重，不删除真实的重执行。缺少depth时无法可靠区分的跨调用记录单列，不静默算入根表。
5. 四节点合并使用所有节点的N之和/对应执行时间之和；不相加各节点TPS，也不对各节点TPS简单平均。并行报告每节点指标以暴露差异。
6. 每批独立输出Mean、Median、nearest-rank P95、N和错误统计；比较下降比例为`1 - R1指标/R0指标`。本轮20条单次冒烟不追加稳定性或CI声明。
7. 该指标刻画VM平均执行成本，包含窗口内的池等待；它不代表节点提交吞吐或CPU服务能力。实际成功提交TPS继续单独按唯一成功交易和墙钟窗口计算，作为辅助。
8. Gas不一致的R0仅作隔离性能参考，不视为正确性基线。安全门槛与指标公式无关：当前Store访问/回收风险仍阻止新并发负载，不能用新指标绕过检查。

现有200条Step-19样本均为成功且单root attempt，上述公式的数值与vm_log_summary.csv一致。compute.normalCal未采样，不能用bigNumCal替代。已保存的20条业务样本筛选作为本次复算集，不把它冒充历史脚本对整份混合日志的原样筛选。
